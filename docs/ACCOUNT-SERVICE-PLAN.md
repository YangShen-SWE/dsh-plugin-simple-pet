## 结论与范围

推荐复用 **DSH 官方 PiAiAdapter 的 ChatGPT OAuth 订阅路径**，增加固定账号的凭据视图和薄账号服务；不是用 OpenAI API Key 替代订阅。官方默认 provider 单槽不代表注入扩展不可能，但也不是现成可用的多账号产品。保留现有第三方后端；不循环切换全局槽、不复制 refresh token、不混用两套认证存储。

备选为每账号独立 CODEX_HOME 加官方 app-server；其进程、权限、工具、存储和版本负担更大，暂不同时建立两套运行框架。官方 AccountSessions 源码类型不等于已发布公共 RPC；内部 token 注入接口不能当稳定公共 API。

## 三方评审与主理人决策

- 产品：把账号管理与收费自动化分授权；每日小任务必须可验收/回退，不把安全基础称作可登录产品。不承诺固定几天交付。
- UX：缺能力、撤销、未知结果、仅对新请求生效的默认账号语义需明确；不增加右键。另记录保存提示可能掩盖后台暂停的风险，单独核验修复。
- 架构：固定 accountRef/epoch、独立 grant 视图、刷新整段互斥、撤销防复活；额度观察不得伪造 fetchedAt 或精确五小时证据。
- 最终取舍：原推荐今日先做未接线凭据视图；架构补充对照后，主理人采纳更小、可立即降低现有耦合的 **T0 既有预热安全策略提取**。凭据视图顺延，今日不做两个任务。后续按明确接口逐步拆分，不进行一次性大重写。

评审材料均为只读意见，不是用户访谈、真实 OAuth、宿主跨进程锁或真实账号验收。公开源码与本机版本不同，兼容性需另测。

## 当前唯一任务 T0 / ADR-001

将 warmupAfterAccountSwitch、multiBlocksLegacy、legacyBlocksMulti 从 index.js 原样移至 warmup-safety.js。index 保留同名导出和内部调用引用；新模块只依赖现有 localSchedule。保留电脑本地日期、DST、保守未来时间阻塞、unknown latch、journal 格式、旧授权和默认开关。

不移动 I/O、定时器、readLegacyWarmup、WARMUP_OWNERS 或调度器；不修改 package/cordis/provider/client/WPF，不新增依赖，不装本地副本。回退为 revert 此独立提交，无用户数据迁移。上传仅源码、新测试及此计划，不加版本/tag/Release/市场。

验收：旧/新导出为同一函数；未知写入锁不可被成功读取解除；跨计划同日/未来 claim 阻塞不变；null/0 等既有语义保持；冻结输入不变；旧公式同域对照；独立时区子进程覆盖午夜、月年边界、春秋 DST；无新增运行副作用。建议命令：`node --test --test-isolation=none warmup-safety.test.js account-control-ui.test.js multi-warmup-ui.test.js`。实际通过数在任务队列与提交交付记录中填写，不以建议冒充结果。

|---|---|---|---|

| T5 暂停状态反馈核验 | T0 | 单独复现保存提示遮蔽暂停；必要时独立双状态展示与受影响 UI 测试 | 不改计划授权、账本、额度或模型调用；无法复现记录理由 |

| T6 官方登录与撤销桥接 | G1 | 先 mock；真实授权后凭据仅宿主 store，取消/重复/刷新竞态安全，DTO 无 grant | 不回滚 refresh token；关闭新 backend 保留旧路径/记录 |
